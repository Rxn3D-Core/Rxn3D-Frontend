Paper slip: direct native print preview

The Lab Case Management page stays in place throughout the print flow.

Recommended flow
Lab Case Management
User clicks Print Paper Slip
→
Hidden print frame
Loads slip 88, data, and images
→
Native print preview
No visible route change

Approaches considered

A

Hidden print frame — recommended

Reuses the existing print route and document. Smallest change, keeps the current URL, supports single and bulk printing.

B

Render inside Case Management

Fetch and mount the paper-slip document directly in the page. Cleaner long-term API, but duplicates print lifecycle and adds more state to an already large page.

C

Temporary blank popup

Avoids route navigation but still opens another window and may be blocked, so it does not match the direct experience as well.

Behavior and safeguards

  • The print action creates one off-screen iframe using the existing /paper-slip/print URL.
  • The print page fetches authenticated data, waits for images, and calls its own frame-scoped print().
  • The parent Lab Case Management route never changes.
  • The iframe is removed after printing or after a bounded cleanup timeout.
  • Invalid selections still use the existing destructive toast; loading failures notify the parent instead of silently failing.
  • Tests cover route construction, frame lifecycle, cleanup, single print, and bulk print.
